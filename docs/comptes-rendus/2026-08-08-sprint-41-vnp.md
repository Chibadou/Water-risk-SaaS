## 3. Erreurs potentielles

### Le trou que j'ai laissé ouvert, et pourquoi

**La définition réglementaire de V_ref n'est pas implémentée.** §4.2a l'exige : celle de l'arrêté ICPE
du 30 juin 2023 modifié le 3 juillet 2024. Le Sprint 38 a mesuré que **Légifrance répond 403 sur les
trois routes, avec l'UA du probe comme avec un UA navigateur**. Je n'ai donc pas pu lire le texte.

J'ai refusé de le reconstituer de mémoire, et c'est le choix le plus important de ce sprint. Une
formule réglementaire approximative produit un chiffre qui **a l'air réglementaire** et contredit la
DREAL — exactement le mode d'échec que la note désigne comme destructeur de confiance client. Un
chiffre absent se voit ; un chiffre faux qui porte l'autorité d'un arrêté ne se voit pas.

Ce que le régime `icpe` signifie donc réellement : « volume déclaré par le site d'après son arrêté
d'autorisation » — le chemin de surcharge que la note prévoit elle-même. **La différence avec
`declare` est l'étiquette**, et la trace d'audit dit explicitement que la définition n'est pas
appliquée. Un test l'exige (`/n'est pas encore appliquée/`).

⚠️ **Risque résiduel** : quelqu'un peut lire « régime ICPE » et croire que l'outil applique l'arrêté.
La trace le démentit, mais elle est dans un `detail`, pas dans un titre.

### Les hypothèses qui peuvent ne pas tenir

- **Le volume journalier est `V_ref / 365`.** C'est plat, et un site industriel ne consomme pas de
  façon uniforme sur l'année — or les restrictions tombent précisément en été, quand beaucoup de
  procédés consomment **plus**. Le VNP est donc probablement **sous-estimé** pour un site à saisonnalité
  estivale, et surestimé pour un site à l'arrêt en août. C'est la limite la plus sérieuse du calcul, et
  elle n'est pas dans le journal d'hypothèses — **elle devrait y être**.
- **La composante structurelle applique une trajectoire nationale à un site.** Le Plan Eau prévoit
  −10 % de prélèvements *nationaux* d'ici 2030, ce qui ne signifie pas −10 % pour chaque site. Le
  journal le dit (« appliquée comme scénario national, non comme une obligation propre à ce site »),
  mais le chiffre reste calculé comme s'il s'appliquait.
- **`resolveVref` accepte n'importe quel volume positif.** Aucun contrôle de vraisemblance : une faute
  de frappe à 365 000 000 m³ passe, et produit un VNP mille fois trop grand.
- **La composante structurelle est un point, pas un intervalle.** Elle hérite de la précision de la
  trajectoire, qui est un chiffre unique de politique publique. Défendable, mais incohérent avec le
  parti pris d'intervalle du reste.

### Non vérifié en conditions réelles

**Tout, et davantage que d'habitude** : ce module n'a jamais reçu de données réelles **ni même de
données simulées**, puisqu'aucune interface ne l'appelle. Ses 40 assertions sont sur fixtures écrites
en même temps que le code — le risque classique du test écrit par l'auteur du code : il vérifie que le
code fait ce que je crois qu'il fait, pas qu'il fait ce qu'il faut.

Le garde-fou le plus solide du sprint n'est pas un test de valeur mais le **test de forme** qui lit le
source : celui-là attrapera une régression que je n'ai pas anticipée.

## 7. Explication à un novice

### 7.1 Le problème, en langage courant

Un arrêté sécheresse dit « réduisez de 50 % ». Réduisez de 50 % **de quoi** ? C'est toute la question
du volume de référence. Si l'entreprise et l'administration ne partent pas du même chiffre, elles ne
parleront jamais du même mètre cube.

Et il y a un piège plus subtil. Une usine qui prend 100 000 m³ dans une rivière et en rend 95 000 à la
même rivière n'en **consomme** que 5 000. Si une restriction lui interdit de prélever, ce qu'elle perd
vraiment n'est pas 100 000 m³ mais 5 000. Entre deux procédés, l'écart est d'un facteur vingt.

### 7.2 Le vocabulaire à connaître

| Terme | Définition |
| --- | --- |
| **VNP** | Volume non prélevable : les m³ qu'une restriction empêche de prendre, sur une année. |
| **V_ref** | Le volume de référence auquel s'applique le pourcentage de réduction. |
| **ICPE** | Installation classée pour la protection de l'environnement : une usine soumise à une autorisation administrative, avec des volumes écrits dedans. |
| **Volume exemptable** | L'eau qu'une restriction ne peut pas toucher : sécurité, défense incendie, santé publique. |
| **Restitution** | La part rendue au même cours d'eau ou à la même nappe. |
| **VNP de crise** | Ce que les restrictions coûtent cette année. |
| **VNP structurel** | Ce que la baisse programmée des volumes autorisés coûtera, indépendamment de la météo. |
| **κ (kappa)** | Le taux de conformité réel : les restrictions sont-elles suivies ? Non estimé, posé à 1. |
| **Journal d'hypothèses** | La liste, produite avec le chiffre, de tout ce qu'il a fallu supposer pour l'obtenir. |

### 7.3 Comment le code s'y prend

**Le refus, avant le calcul.** La première chose que fait `computeVnp` n'est pas de calculer :

```ts
if (vref.regime === "indisponible" || vref.volumeM3 === undefined) {
  return {
    available: false,
    kappa, hypotheses,
    vrefDetail: vref.detail,
    message: "Volume de référence non déclaré — le VNP ne peut pas être calculé.",
  };
}
```

Il aurait été facile de rendre `0`. Un zéro se lit « rien ne sera bloqué » ; l'absence se lit « on ne
sait pas ». Ce sont deux affirmations opposées, et le dépôt a déjà payé cette confusion trois fois.

**L'interdiction d'agréger, portée par le type.** L'anti-pattern n°3 dit : ne jamais additionner le VNP
de crise et le VNP structurel. On pourrait l'écrire en commentaire et espérer. Le code fait autrement :
`VnpResult` expose `crise` et `structurel`, **et aucun champ qui les combine**. Le seul accesseur les
rend séparés :

```ts
export function vnpComponents(result: VnpResult) {
  const out = [];
  if (result.crise) out.push({ id: "crise", label: "VNP de crise", value: result.crise });
  if (result.structurel) out.push({ id: "structurel", label: "VNP structurel", value: result.structurel });
  return out;
}
```

Et comme une contrainte de forme ne se teste pas sur des valeurs, le test lit le **texte du module** :

```ts
const src = readFileSync("lib/vnp.ts", "utf-8");
const sums = [/crise\s*\+\s*structurel/, /total\s*[:=]\s*.*structurel/, …];
check("shape: no expression in lib/vnp.ts adds the two components",
  !sums.some((re) => re.test(src)));
```

Le jour où quelqu'un ajoutera un `total` par commodité, la suite rougira — au lieu de dépendre de
l'œil d'un relecteur. C'est le même patron que le test miroir qui garde `DEPENDANCE_FACTOR` en phase
entre deux fichiers.

**Prélever n'est pas consommer**, et le journal le dit quand il ne sait pas :

```ts
} else {
  hypotheses.push(
    "Taux de restitution non déclaré : le VNP porte sur le volume PRÉLEVÉ, non sur la " +
      "consommation. Pour un procédé qui restitue l'essentiel de son eau au même milieu, " +
      "le chiffre est surestimé — d'un ordre de grandeur dans le cas d'un refroidissement " +
      "en circuit ouvert.",
  );
}
```

Le chiffre sort quand même. Mais il sort **avec la phrase qui dit dans quel sens il est faux**.

### 7.4 Pourquoi ces choix plutôt que d'autres

- **Pourquoi ne pas implémenter la définition réglementaire ?** Parce que je n'ai pas pu lire le texte
  (Légifrance renvoie 403), et qu'une formule réglementaire approximative est plus dangereuse
  qu'absente : elle produit un chiffre qui semble opposable et ne l'est pas.
- **Pourquoi un test qui lit le code source ?** Parce que l'interdiction d'agréger est une propriété de
  **forme**, pas de valeur. Aucun jeu de nombres ne peut prouver qu'un champ n'existe pas.
- **Pourquoi κ = 1 plutôt qu'une estimation ?** Parce que ces chiffres passeront devant un vérificateur
  tiers, et que la note est claire : il accepte une hypothèse conservatrice **déclarée** et rejette un
  coefficient empirique mal identifié. Le journal écrit donc « VNP NOMINAL, hypothèse volontairement
  conservatrice ».
- **Pourquoi un journal d'hypothèses plutôt qu'une page de documentation ?** Parce qu'une page se lit
  une fois et se périme. Le journal est **produit avec le chiffre**, donc il voyage avec lui jusqu'à
  l'export — c'est ce que l'ADR-006 demande.

### 7.5 Pour expérimenter soi-même

**a) Mesurer le facteur 19.**

```bash
npx tsx scripts/test/vnp.test.ts
```

Cherchez les deux lignes « restitution: 95 % returned → the VNP falls to 5 % » et « 5 % returned →
95 % of the volume ». Même volume prélevé, même arrêté, **facteur 19** sur le VNP. C'est pourquoi la
note qualifie ce champ d'obligatoire.

**b) Essayer d'agréger, et se faire arrêter.** Ajoutez dans `lib/vnp.ts`, à la fin de `computeVnp` :

```ts
// tentative d'ajout d'un total « pratique »
const total = (crise?.min ?? 0) + (structurel?.min ?? 0);
```

Relancez la suite. **Un seul test tombe, et c'est le bon** — vérifié : « shape: no expression in
lib/vnp.ts adds the two components ». Il ne tombe pas parce qu'une valeur est fausse, mais parce que
**l'expression existe**. Vous venez de vérifier qu'une règle de conception peut être défendue par un
test plutôt que par un commentaire.

**c) Voir un refus motivé.** Dans le fichier de test, remplacez `resolveVref({ volumeDeclareM3: 365_000 })`
par `resolveVref({})` dans la fonction `base`, et relancez. La plupart des tests tombent, et le message
qui accompagne l'échec est la phrase que verrait l'utilisateur : « Volume de référence non déclaré — le
VNP ne peut pas être calculé. » Comparez avec ce qu'aurait donné un `return 0` : un tableau rempli de
zéros, indiscernable d'un site sans risque.
